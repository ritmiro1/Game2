# LifeOS Virtual Display — экспериментальные исходники, НЕ готовый production-драйвер

Цель: настоящий дополнительный монитор Windows даже при одном физическом экране.
Оконная оболочка и полный экран эту задачу не выполняют.

## Что включено

- Адаптация официального Microsoft Indirect Display Driver Sample на UMDF/IddCx.
- Один монитор вместо нескольких, имя EDID `LifeOSDisplay`, исправленная контрольная сумма.
- Собственные hardware ID и группа изоляции `LifeOSVirtualDisplay`.
- Программа `LifeOSDisplayDevice.exe`, которая держит software device живым до выхода.
- В Electron-приложении: перечисление реальных дисплеев, перенос оболочки и Viewer
  через desktopCapturer / getDisplayMedia **если output поддерживает захват**.
- Viewer пересылает ввод в окна LifeOS/Chromium, не в произвольные Windows-программы.

## Что НЕ выполнено

- Сборка и аппаратные испытания драйверного DLL на Windows-стенде.
- Production-подпись / проверенная установка под Secure Boot.
- Гарантия захвата каждого IDD output на каждой GPU и в RDP-сессиях.
- Полноценное удалённое управление всеми внешними Windows-окнами.

Исходники не следует представлять как готовый установленный монитор. Программа устройства
сама по себе не устанавливает INF и не доказывает успешный запуск драйвера.

## Сборка

1. Использовать отдельный Windows 11 x64 тестовый стенд с возможностью восстановления.
2. Установить совместимые Visual Studio C++, Windows SDK, WDK и расширение WDK для VS.
3. Открыть `driver/LifeOSVirtualDisplay.vcxproj`, проверить выбранные SDK/WDK,
   собрать `Release | x64`. Проект использует WPP; сборка создаёт Driver.tmh.
4. Проверить INF, версию, каталоги, правила установки и подписи для целевой Windows.
5. Собирать device host через `device/build.cmd` в x64 Native Tools Command Prompt.

Для воспроизводимой проверки компиляции имеется отдельный GitHub Actions workflow
`LifeOS experimental driver compile check`: восстанавливает официальные NuGet SDK/WDK
из `packages.config`, выполняет MSBuild с выключенной подписью и сохраняет логи и
`compile-status.json`. Результат CI — только проверка компиляции, **не доказательство**
установки, появления монитора, Secure Boot-совместимости или работы Viewer.
Локально `nuget restore packages.config -PackagesDirectory packages` подготавливает те же версии.
Для VS 2022 зафиксированы официальные SDK/WDK NuGet 10.0.26100.6584
(набор версий из upstream commit `920da97b3db747167926e1ec8977515001f6a567`).
Исходники самого драйвера происходят из более нового commit, указанного ниже.
Зависимости `packages/` не включать в Git или исходный ZIP.


Установка драйвера — отдельная процедура на стенде с подходящим подписанным пакетом.
Здесь намеренно нет скрипта отключения Secure Boot / проверки подписей и нет скрытого
включения test mode. Обычному пользователю не требуется менять настройки защиты ради EXE.

После корректной установки пакета можно запустить device host с `--enable`.
Он автоматически закрывает software device через 10 минут; X/Ctrl+C завершают раньше.
Физический монитор нужно оставлять включённым и основным. После появления дисплея
открыть Настройки LifeOS → Экран и Windows → Проверить дисплеи.
Перенести LifeOS на созданный дисплей и открыть Viewer на физическом.
Если capture не работает, не считать этот путь завершённым; требуется доработка транспорта.
