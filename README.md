# LifeOS · 0.1.0 preview

Личное цифровое пространство для Windows: рабочий стол, окна, приложения, Chromium-браузер и самостоятельный веб-поиск.

> **Предварительная версия, не «всё готово».** Виртуальный дисплей — экспериментальный исходный проект, не подписанный установленный драйвер. Поиск имеет ограниченный реальный индекс, не охват всего интернета. Личные данные пока не зашифрованы.

## Скачать

Готовые проверенные Windows-сборки публикуются как prerelease в [GitHub Releases](https://github.com/ritmiro1/Game2/releases).

- `LifeOS-0.1.0-Setup-x64.exe` — установщик для текущего пользователя.
- `LifeOS-0.1.0-Portable-x64.exe` — портативный запуск. **Данные остаются в пользовательском AppData**, а не рядом с EXE.
- `LifeOS-0.1.0-SearchServer.zip` — исходники серверной части.
- `LifeOS-0.1.0-VirtualDisplay-source.zip` — экспериментальные исходники драйвера.
- `LifeOSDisplayDevice-experimental.exe` — хост software device для тестового стенда; **это НЕ драйвер**.
- `Windows-smoke.json`, `SHA256SUMS.txt` — результат запуска упакованного EXE и контрольные суммы.

EXE в preview не подписан. Не отключайте защиту Windows и не запускайте незнакомые файлы от администратора ради приложения. Проверяйте происхождение и SHA256. Основная оболочка не требует административных прав.

## Что реализовано

- Рабочий стол, док, меню запуска, поиск команд, перемещаемые/изменяемые окна, три пространства, восстановление раскладки, светлая/тёмная тема и акценты.
- Задачи: список/канбан, сроки, приоритеты, проекты, зависимости с проверкой циклов, повторения, идемпотентное завершение.
- Заметки и дневник: автосохранение, обнаружение конфликтов, простой безопасный Markdown-preview, экспорт.
- Календарь: реальные события, время, проекты и ICS-экспорт. **Повторения событий / ICS-импорт ещё не реализованы.**
- Проекты со связанными задачами, заметками, закладками и вычисляемым прогрессом.
- Ежедневные привычки с историей отметок; без искусственных показателей.
- Фокус: таймер с паузой, сохранение сессий и завершение при закрытом внутреннем окне, пока работает LifeOS.
- Финансы: ручные доходы/расходы в RUB, категории, месяц и CSV-экспорт; без банковских интеграций.
- Материалы: закладки, выбранные файлы, реальные загрузки Chromium.
- SQLite, транзакции, локальный полнотекстовый индекс, JSON-экспорт/импорт и автоматическая копия перед восстановлением.
- В EXE: отдельные WebContentsView, профили cookies, непостоянные приватные сессии, разрешения, вкладки, загрузки, безопасный контролируемый IPC.
- Собственный веб-поиск: HTTP-обходчик, robots.txt, лимиты, SSRF-защита с закреплением публичного DNS-адреса, SQLite FTS5, ранжирование, даты, обновления и удаление документов.

## Что пока не завершено

- Production-подпись, установка и аппаратная валидация виртуального дисплея.
- Подтверждённый сквозной IDD → Windows → capture → Viewer на физическом стенде.
- Широкое покрытие интернета, зрелый антиспам, русская морфология, отдельный индекс изображений/видео и ленты новостей.
- Облачная синхронизация, полное шифрование, сторонние плагины, ИИ, парольный менеджер.
- Полный аудит безопасности браузера и совместимости DRM/расширений. Не используйте preview как единственный браузер для критичных аккаунтов.
- Напоминания при полностью завершённом приложении; режим фокуса не блокирует чужие программы.

Полная [продуктовая спецификация](docs/LifeOS-specification.ru.md) — целевой план, **не перечень уже реализованного**. Для состояния выпуска ориентируйтесь на этот README и release notes.

## Разработка и веб-предпросмотр

Нужен Node.js **22.13+** (с `node:sqlite` и FTS5).

```bash
npm ci
npm test
npm run build
npm run preview
```

Открыть адрес сервера на порту 3101. Он слушает `0.0.0.0`; клиент использует относительные `/api` URL.
Это локальный/dev-предпросмотр с общим профилем, **не многопользовательский публичный сервис**. Не открывайте его всем в интернете с личными данными.

Для Vite hot reload: в одном терминале `npm run preview`, в другом `npm run dev`. Vite проксирует `/api` на backend.

Веб-предпросмотр не имеет доступа к дискам, встроенному WebContentsView и мониторам. В нём веб-страницы открываются отдельными вкладками. Эти различия обозначены в интерфейсе.

В ограниченной среде без загрузки Electron-бинарников: `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm ci`; веб-предпросмотр и core-тесты продолжат работать. Для `npm start` нужен настоящий установленный Electron binary.

## Настольный запуск и сборка

```bash
npm ci
npm run build
npm start
npm run dist:win
```

Windows CI выполняет core-тесты, TypeScript/Vite build, запуск Electron, сборку NSIS/portable, запуск **упакованного** EXE и компиляцию software-device host. Успех CI не является аппаратным тестом драйвера.

## Собственный актуальный интернет-поиск

По умолчанию EXE запускает собственный **локальный** индекс. Это не Google/Bing и не ответы из памяти ИИ. Источники можно добавлять в Настройки → Поисковая система. При первом запуске индекс пуст: нужен успешный реальный обход. Начальный набор — официальные технологические разделы и несколько публичных источников; некоторые сайты могут запрещать обход или быть недоступны.

Обход выполняется при работающем приложении; каждые 30 минут проверяются постоянные очереди в SQLite (по умолчанию три страницы на источник за проход; до 1000 URL на источник, глубина два перехода). Пока это пилотная инфраструктура. Поддержано обнаружение ссылок из RSS/Atom/sitemap и alternate-feed в HTML. Широкая непрерывная индексация и отдельный новостной конвейер ещё не завершены. Очередь переживает перезапуск: постепенно открываются новые страницы, а ранее полученные повторно проверяются. robots.txt и noindex соблюдаются; после 404/410 документ исчезает из выдачи. Сайт без корректной даты не становится «опубликованным сегодня» после загрузки.

Никаких тайных внешних поисковых API нет. Доступные веб-результаты зависят от настоящего покрытия индекса. Поиск по заметкам — отдельная функция оболочки.

### Постоянно работающий backend

```bash
# Node.js 22.13+
npm ci --omit=dev --ignore-scripts
LIFEOS_DATA_DIR=/your/persistent/path npm run search
```

В PowerShell переменные задаются через `$env:LIFEOS_DATA_DIR='C:\LifeOS-search'`.
Или использовать `Dockerfile` / `compose.yaml`:

```bash
# Set LIFEOS_ADMIN_TOKEN to a long random secret in your environment first.
docker compose up --build -d
```

Compose публикует API только на loopback. Для удалённого доступа поставьте HTTPS reverse proxy с лимитами, подходящей сетевой политикой и мониторингом. В EXE укажите HTTPS origin в настройке сервера. Личные заметки и cookies серверу не отправляются, но сам веб-запрос неизбежно передаётся.

API:

- `GET /healthz` — состояние процесса.
- `POST /api/search` JSON `{ "query": "Node", "period": "all" }` — `{data: ...}` с выдачей.
- `GET /api/search/status` — охват и состояние источников.
- `POST /api/rpc` с действиями `addSource`, `removeSource`, `crawl` — только с `Authorization: Bearer <LIFEOS_ADMIN_TOKEN>` в search-only режиме.
- Пример добавления: `{ "action": "addSource", "args": { "title": "Источник", "url": "https://example.org/news/" } }`.

На публичном search-only сервере **нет доступа к локальным задачам, заметкам, экспорту или системным операциям**. Дополнительная защита от злоупотреблений и распределённые лимиты нужны перед широким публичным запуском.

При корпоративном TLS используйте доверенный `NODE_EXTRA_CA_CERTS`; код **не отключает проверку сертификатов**. Для ограниченных стендов можно задать `LIFEOS_CRAWL_ALLOWED_HOSTS=github.com,api.github.com`.

## Данные

EXE использует `app.getPath('userData')` (Windows AppData), локальный сервер — `.lifeos` или `LIFEOS_DATA_DIR`. Отдельные `lifeos.sqlite`, `web-index.sqlite`, JSON-копии в `backups`. Не удаляйте SQLite WAL-файлы при работающем приложении.

JSON-копия включает записи и настройки, но не содержимое выбранных внешних файлов, cookies или пароли. Полное шифрование не реализовано. Храните экспорт безопасно.

## Виртуальный монитор

См. [native/virtual-display/README.ru.md](native/virtual-display/README.ru.md). Исходники адаптированы из Microsoft IddSample с сохранением лицензии. Драйвер в установщик не устанавливается. Windows самостоятельно нумерует мониторы; постоянная цифра «2» не гарантируется.

Viewer доступен только для реально существующего неосновного дисплея. Он не подменяет отсутствие виртуального монитора. Для сторонних Windows-окон полноценная передача ввода не реализована.

## Проверки

```bash
npm test
npm run build
npm run test:e2e  # with preview running on port 3000, or set LIFEOS_TEST_URL
```

Тесты покрывают сохранение/удаление/восстановление, конфликты, циклы задач, повторы и календарные границы; настоящий путь обновления тестового документа через обходчик в индекс; robots.txt, даты, источники и SSRF. UI-проверки используют отдельные тестовые записи и не подменяют веб-результаты демонстрационными данными.
